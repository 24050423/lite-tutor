# Lite-Tutor 项目改进计划

本文是后续实施和验收的依据。各阶段按依赖顺序推进，阶段内的指标为拟定验收标准。

## 1. 目标与范围

把 Lite-Tutor 改进为能核对课件依据、能根据练习结果安排复习的本地课程助手。用户能选择课程资料，提问并核对原页，按章节练习，再根据失分原因完成下一项复习任务。

面向在 Windows 个人电脑上自主复习的学生。沿用 Streamlit、FastAPI、ChromaDB 和现有模型接口，优先复用资料预览、历史会话、测验、错题本及掌握曲线。多人协作、账号权限、图谱检索、独立搜索服务和前端框架迁移暂列后续研究。

## 2. 当前基线

- `doc_ingest.py` 负责保存原件、生成预览和提取文本。能获取页码的格式用正文标记页码。`rag_builder.py` 的索引主要按资料来源名记录切片。同名替换会创建新的文档 ID，旧知识库还有缺少原件的条目。
- `/search` 和 `/quiz` 已在当前开发工作区共用向量与关键词召回逻辑。关键词覆盖率和向量得分分别过滤，再按名次融合。临时库验证已通过，真实课程资料上的检索效果仍需建立基线。
- `app.py` 从检索文本提取页码。多份资料的同页号难以区分，历史消息接口目前只保存角色和正文。
- 测验、评分、错题和统计已有入口。练习记录按会话保存，知识点主要由关键词推导，缺少稳定标识和统一的复习任务。

计划参考 DeepTutor 的独立召回与排名融合，以及带有文档和页信息的出处对象。Lite-Tutor 的具体方案以本地数据格式和现有页面为准。

- [DeepTutor 原页定位实现](https://github.com/HKUDS/DeepTutor/blob/4c1e000d8563c5ac3b231baaaf149dc4dc4d2406/deeptutor/services/rag/source_pages.py)

## 3. 实施阶段

| 阶段 | 优先级 | 交付物 | 依赖 |
| --- | --- | --- | --- |
| 0. 建立基线 | P0 | 评测样例、现状结果和旧数据验证样本 | 无 |
| 1. 资料与引用 | P0 | 可定位的片段、引用卡片、历史引用、迁移流程 | 阶段 0 的基线记录 |
| 2. 检索与对话 | P0 | 资料范围控制、检索评测对比、依据明确的对话 | 阶段 1 的片段与引用结构 |
| 3. 测验与评分 | P1 | 带出处和评分要点的题目、逐项反馈、变式重练 | 阶段 1–2 的引用和检索 |
| 4. 学习路径 | P1 | 课程目标、待复习清单、统一知识点统计 | 阶段 3 的题目和答题记录 |

第一期发布目标是阶段 0–2，能演示资料上传、限定范围提问和引用回看。第二期完成阶段 3–4，能演示从失分反馈到变式重练的连续流程。每个阶段独立验证，切换新存储或排序前先保留可回退版本。

### 阶段 0　建立可复现的基线

1. 选至少两份课程资料，包含同页号、相近题号和会重复出现的概念。另准备无预览资料、仅有旧切片的资料和同名更新样本。评测用课件须允许共享，私人课程资料仅保存在本机。
2. 准备至少 30 个评测问题，覆盖中文术语、缩写、题号、同义问法和限定资料。至少 8 个问题在指定范围内无答案，其中包括术语相近但无法作答的干扰案例。对有答案的问题人工标注正确文档和页码或可接受片段。
3. 在相同资料、嵌入模式和机器上记录现有检索的前 4 条正确出处命中率、无答案误命中数、检索 P95 耗时。命中率统计可回答问题，误命中数统计无答案问题，耗时单独测量本地检索，记录样本数和运行条件。
4. 保留一套不含私有内容的旧格式会话、答题记录和资料索引样本，供后续兼容性验证。

### 阶段 1　资料入库与可点击引用

- **资料入库。** `doc_ingest.py` 能按原页定位时，将页内文本及页号交给 `rag_builder.py` 切片。PDF 用原件页码。Office 文档只有在能与预览稳定对齐时才标注预览页码。只有文本时仍可检索，引用展示文件名和摘要。
- **检索与引用结构。** 设计可选片段字段，包括切片 ID、资料 ID、显示名、版本及页码。区分检索返回的候选片段和回答实际标出的引用。模型只从本轮候选中选择引用编号，界面按后端返回的资料信息解析并忽略未知编号。
- **前端和历史。** 在 `app.py` 的对话和题目下显示课程资料名、原页和可展开片段。复用 `/document/{doc_id}/preview`，验证定位页码的实际表现。扩展 `/chat_history` 的校验和持久化，使新消息可保存引用快照，旧消息仍按原格式读取。
- **替换与删除。** 为每次入库的资料版本建立明确身份。先在暂存状态准备新文件和新索引，验证成功再发布。新版本启用后停止检索旧版本。历史引用若指向已删除或被替换的版本，显示出处名称和不可用提示，避免打开新版的同页号。

**验收标准。** 导入两份都含第 5 页的课件，问答引用能打开各自正确的预览页，刷新会话后仍可查看。无页码资料只显示文件名和片段。模拟更新中途失败后，旧资料仍可检索。成功替换后，旧引用明确显示状态。

### 阶段 2　检索质量与依据明确的对话

- **限制检索范围。** 在对话提供资料范围选择，测验复用相同的范围标识。向量和关键词两路都按同一范围过滤。无命中时保留用户选择，明确告知当前范围未检索到依据。
- **评估排序。** 保留当前覆盖率与排名融合作为对照，评估 BM25 等本地关键词评分。需要时对少量候选做重排，先测中文术语、题号和同义问法，再决定是否启用。分别观测向量和关键词门槛，避免不同分数含义造成误判。
- **回答与异常反馈。** 将课件片段交给现有模型时附带引用编号。前端区分课件依据和通用知识补充，检索超时、资料为空和知识库未启用分别给出对应状态。向量故障时仍可走关键词检索。
- **处理嵌入兼容。** 启动时核对现有集合的嵌入配置和实际模型。已有 `sentence_transformer` 索引保持与原模型匹配。模型加载失败时提供明确状态，避免静默用哈希向量查询不兼容的集合。

**验收标准。** 使用阶段 0 相同的样本重测。前 4 条正确出处命中率不得下降，无答案误命中数不得增加，至少一项有所改善。本地检索 P95 耗时的初始预算为基线的 120%。超出时保留现有排序，并记录对比结果。限定范围用例全部通过，切换嵌入失败及后端超时均能显示明确状态。未达到验收门槛的评分或重排策略暂缓发布。

### 阶段 3　测验、评分与重练

- **结构化题目。** 在既有 `/quiz` 结果上扩展题目标识、知识点、出处和评分要点。出题返回后校验结构及引用是否来自本题候选。通用题显示来源类型，允许用户查看出题范围。
- **逐项反馈。** `/grade` 返回命中、遗漏和对应解释，原始回答和评分方式一起记录。模型失败时走现有关键词评分并标明该方式。以人工标注的标准答案、同义表达、部分正确和错误答案检查判分一致性。
- **同知识点重练。** 错题入口使用原题的知识点和可用资料生成变式，保留旧题记录。遇到旧记录缺少知识点标识或原资料不可用时，使用已记录的主题生成练习，并在页面标明当前依据。

**验收标准。** 完成一道来源可核对的题，看到逐项失分说明，并从错题生成同一知识点的新题。模拟一次模型超时、一次重复提交，确认界面会反馈状态，重复提交最多统计为一次练习。

### 阶段 4　学习路径与界面

- **建立课程与知识点。** 用户选择课程资料，手动确认章节或生成后可编辑的知识点列表。同名知识点按课程隔离。每道结构化题和每条新答题记录都能关联知识点。
- **生成复习清单。** 根据错题、距离上次练习的时间和近期答题情况排优先级。显示每项任务的原因，支持进入练习、完成和稍后复习，重启后恢复状态。
- **统一反馈。** 掌握曲线、错题本和思维导图读取同一套知识点与练习记录。旧记录继续可查，无法可靠归类的记录保留为待归类。
- **串联入口。** 按「选资料 → 学习或练习 → 查看反馈 → 继续复习」组织导航，复用现有页面，补齐空状态和操作反馈。

**验收标准。** 为一门课程设定复习目标，完成一次测验后出现可解释的复习项。完成变式题后，清单和知识点统计同步更新。重启后状态可恢复，同名知识点在不同课程中分别统计。

## 4. 数据、接口与迁移

- `doc_ingest.py` 负责资料版本、页级解析和文件状态。`rag_builder.py` 负责切片、检索范围和候选排序。`server.py` 承担参数校验、现有接口和记录持久化。`app.py` 负责显示和用户操作。等数据约定稳定后，再按独立职责拆分模块。
- 兼容 `/search` 的 `status`、`context`、`fallback_required`、`confidence`，以及 `/quiz` 的 `quiz`、`keywords`、`context`。新增字段采用可选结构，先验证当前对话、测验和工具调用路径。若必须改变已有字段语义，先更新调用方并记录版本差异。
- 支持旧 `chat_db.json`、`learning_db.json`、`documents_db.json` 和 Chroma 索引。仅依据已有来源名展示时只作文本引用，补页码优先从可用原件逐份重新提取。缺少原件的旧切片保留检索能力，无需为升级删除旧库。
- 迁移前关闭后端，备份 `chroma_db/`、`documents/` 和上述 JSON。先在副本上检查文档及记录数量、抽样引用和旧会话。迁移按资料版本记录进度，允许失败后重试。发布前试演恢复备份，明确回退时间点及该时间点之后学习记录的保留方式。
- 文件预览按服务端登记的资料和版本定位。路径和页码由服务端校验，资料名及正文按文本展示。解析、索引和学习记录留在本机。沿用已配置的模型服务，并在界面说明问答或出题会发送问题和相关课件片段。新增检索、迁移和评测在本地运行。

## 5. 测试与最终验收

- **单元与接口测试。** 覆盖切片跨页、无页码、页码重复、版本不一致、两路范围过滤、无答案、历史兼容和评分解析。接口测试用临时 ChromaDB 和模拟模型回复，核对响应字段与实际写入结果。
- **集成与恢复测试。** 用 Windows 启动脚本检查两期功能。覆盖上传、替换、删除、预览、会话恢复、重复提交和索引迁移失败。使用副本验证回退后仍可打开旧资料和历史记录。
- **检索与判分样例。** 用固定样例报告命中率、误命中数和耗时，保留失败问句及原因。判分另外抽样对照人工评分，记录模型评分和关键词降级的差异。
- **演示流程。** 上传两份数据结构课件 → 限定资料提问 → 点击出处打开正确原页 → 按章节出题 → 提交部分正确的答案并查看逐项反馈 → 在复习清单完成变式题 → 重启后检查历史和进度。

第一期验收以可核对的出处和检索对比结果为准。第二期验收增加逐项评分、变式重练和进度恢复。每期交付包括代码、部署与迁移说明、测试结果及未达标项。
